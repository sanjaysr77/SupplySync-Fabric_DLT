# Starting a New Fabric Project from This Network

This note assumes you want to keep only the Fabric network setup and start a fresh project from this repository. You are not using the backend app yet; you are only reusing the network definition, certificates, Docker compose, and chaincode deployment flow.

## 1. Clean generated artifacts first

Remove any generated Fabric artifacts so the project starts clean:

- `rm -rf organizations/`
- `rm -rf channel-artifacts/`
- `rm -f asset_1.0.tar.gz`
- `rm -f block2.pb`

> These are generated by `./network.sh` and `./scripts/deploy-channels.sh`, so they are safe to delete.

## 2. Keep the source files and scripts

Do not delete these directories and files: they are the template for the new network.

- `chaincode/`
- `config/`
- `configtx/`
- `docker/`
- `scripts/`
- `network.sh`
- `deploy-all-chaincodes.sh`
- `set-anchor-peers.sh`
- `README.md`
- `USERGUIDE.md`

## 3. Priority changes to make this a new project

### 3.1 Update organization names and domain

These are the most important changes if you are cloning this for a new business network.

- `configtx/configtx.yaml`
  - Change organization names: `BuyerMSP`, `SellerMSP`, `OrdererMSP` (or whatever fits your new orgs)
  - Change domain names: `buyer.example.com`, `seller.example.com`, `example.com`
  - Change channel profile and channel name if needed.

- `docker/docker-compose-network.yaml`
  - Update container hostnames and organization names if you rename orgs.
  - Update peer ports if you want different host ports.

- `docker/docker-compose-ca.yaml`
  - Update CA container names and CA ports if your new org names change.

- `scripts/ca-functions.sh`
  - Update registration/enrollment names only if you change org names or domain values.

- `scripts/deploy-channels.sh`
  - Update the channel profile name (`TwoOrgsChannel`) or channel ID (`mychannel`) as needed.
  - Update org MSP values if you rename the org MSP IDs.

### 3.2 Update network shell script if needed

- `network.sh`
  - You usually do not need to change this unless you rename the channel creation or artifact locations.
  - If you rename `configtx/`, update `FABRIC_CFG_PATH`.

### 3.3 Update chaincode metadata for your new project

- `scripts/deploy-chaincodes.sh`
  - `CC_NAME`: the chaincode name
  - `CC_SRC_PATH`: points to your chaincode directory
  - `CC_VERSION`: initial version should be `1.0`
  - `CC_SEQUENCE`: set to `1` for the first deployment
  - `CC_POLICY`: endorsement policy for your orgs

- `chaincode/asset/asset.go`
  - Rename the chaincode package and file structure if the business domain is different.
  - Replace asset model fields with your own business data.

- `chaincode/asset/collections_config.json`
  - Update private data collection definitions if your new project needs different collection policies.

## 4. Recommended order of changes

1. **Rename orgs and domains** in `configtx/configtx.yaml` and `docker/docker-compose-*.yaml`
2. **Update `scripts/ca-functions.sh` and `scripts/deploy-channels.sh`** to use the new org names and channel ID
3. **Update `scripts/deploy-chaincodes.sh`** for your new chaincode name, version, and sequence
4. **Change chaincode source** in `chaincode/asset/` to match your new domain
5. **Clear generated files** (`organizations/`, `channel-artifacts/`, `*.tar.gz`)
6. **Start the network** with `./network.sh up`
7. **Create the channel** with `./network.sh createchannel`
8. **Deploy chaincode** with `./network.sh deploycc`

## 5. If you are starting only the network (skip backend)

- You can ignore `gateway-app/` for now.
- The network is usable with CLI scripts and Fabric SDK later.
- If the backend is not needed yet, do not worry about `gateway-app/config/networkTopology.js`, `gateway-app/server.js`, or `gateway-app/routes/*`.

## 6. Quick commands for a clean new start

```bash
rm -rf organizations/ channel-artifacts/ asset_1.0.tar.gz block2.pb
./network.sh up
./network.sh createchannel
./network.sh deploycc
```

## 7. What to change if you want a new channel name

- `scripts/deploy-channels.sh`: change `mychannel` and the profile name used by `configtxgen`
- `scripts/deploy-chaincodes.sh`: change `CHANNEL="mychannel"` to your new channel ID
- Any CLI or gateway config that hardcodes `mychannel`

## 8. What to change if you want a different org count

This repo is built for 2 orgs. If you need more orgs, you must change:

- `configtx/configtx.yaml`
- `docker/docker-compose-network.yaml`
- `docker/docker-compose-ca.yaml`
- `scripts/ca-functions.sh`
- `scripts/deploy-channels.sh`
- `scripts/deploy-chaincodes.sh` (endorsement policy and peer addresses)

## 9. Keep this workflow in mind

- `./network.sh up` = start the network infrastructure
- `./network.sh createchannel` = create/join the channel
- `./network.sh deploycc` = install, approve, and commit chaincode
- `./network.sh all` = run all three steps in order

## 10. Final advice

For a clean new project, change the names in config and Docker first, then regenerate certificates and channel artifacts from scratch. That gives you a reliable base without stale files from the old network.
